# v0.1.2 Release Package Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish annotated tag `v0.1.2` as an immutable GitHub Release with a verified `VAYZRA-v0.1.2.tar.gz` source package and `SHA256SUMS`.

**Architecture:** The existing `github-release` validation job remains the trust gate. It will build a reproducible source archive from the exact peeled tag commit and transfer the two release files through a pinned workflow artifact; the minimal write-permission publish job will download and revalidate them, create a draft Release with both assets, publish it, and require GitHub to report `immutable=true`.

**Tech Stack:** GitHub Actions YAML, Bash, Git, GNU tar/gzip/coreutils, GitHub CLI, existing `scripts/github-ota_contract_test.sh`.

## Global Constraints

- The only accepted version is stable SemVer tag `v0.1.2`, created as an annotated tag on the final verified `master` commit.
- The Release assets are exactly `VAYZRA-v0.1.2.tar.gz` and `SHA256SUMS` in addition to GitHub's automatic source archives.
- The archive has exactly one safe top-level prefix, `VAYZRA-v0.1.2/`, and is produced with `git archive` plus `gzip -n`.
- `SHA256SUMS` contains a portable relative filename, never a runner temporary path.
- The Release is a draft while assets are attached and is published only after checksum and archive validation.
- The finished Release must be non-draft, non-prerelease, contain both expected assets, and report `immutable=true`.
- No npm package, GitHub Packages registry artifact, container image, SBOM, Phase 6 manifest, or production deployment is added.
- All third-party GitHub Actions remain pinned to full 40-character commit SHAs.
