# HappyLearn Phase 4 AI 答疑、兼容网关与用量设计规格

日期：2026-07-26  
状态：已由用户逐节确认，待书面规格复核

## 1. 目标

Phase 4 在已完成的认证、教学文件、老师答疑和通知能力上增加私密 AI 答疑。老师可以安全配置 OpenAI 兼容供应商、模型、提示词和额度；学生可以使用文字、图片、PDF 和 Word 发起 AI 答疑，并通过可恢复的流式界面获得完整解答。

本阶段必须同时满足：

1. 每个逻辑运行最多触发一次不可安全重放的供应商调用。
2. 页面刷新、SSE 断线和重复点击不重复调用，也不重复记账。
3. 请求数和 Token 数执行每日、月度硬额度；费用只统计展示，不参与拦截。
4. 失败尝试不消耗学生硬额度，但必须保留脱敏失败与未知上游用量记录。
5. 学生只能访问自己的 AI 与老师答疑；老师配置和密钥绝不暴露给学生。
6. 保持目标 Ubuntu 24.04、2 核 4 GB 单机部署可运行、可测试、可恢复。

## 2. 已确认的产品边界

### 2.1 供应商与模型

- 同时支持 OpenAI 兼容的 Chat Completions 和 Responses 流式模式。
- 可以保存多个供应商配置，但同一时间只启用一个主供应商。
- Phase 4 不做自动供应商故障切换。
- 老师配置文本模型和视觉模型；学生不能选择底层供应商或模型。
- 纯文字、PDF 和 Word 使用文本模型；文档先通过现有安全处理流程提取文本。
- 只要问题上下文包含图片，就使用视觉模型。
- 附件未完成扫描/处理或提取失败时不调用 AI，并向学生返回明确状态。
- AI 问题必须选择“数学”或“物理”，据此选择版本化提示词；模型仍由老师端路由。

### 2.2 额度与费用

- 全站和单学生均支持每日/月度请求数、每日/月度 Token 数限制。
- 单学生字段语义沿用总设计：`NULL` 继承全站默认，`0` 禁用对应能力，正数表示上限。
- 请求和 Token 是硬限制；费用只统计和展示。
- 运行创建时先原子预留额度，成功后按实际或明确标记的估算 usage 结算。
- 失败或取消时释放硬额度预留；若请求可能已到达供应商但 usage 不可知，保留“上游用量未知”审计状态，不伪造零用量。

### 2.3 流式恢复与重试

- 浏览器使用服务器发送事件（SSE）读取运行事件。
- 浏览器断线后携带最后事件序号恢复读取同一个运行，不重新调用供应商。
- 浏览器连接生命周期不控制后台供应商调用；关闭页面不会自动取消运行。
- 只有运行进入明确失败或取消状态后，学生才能主动创建新尝试。
- 重试创建新的 attempt，保留原始学生消息和旧尝试历史，并使用幂等键防止重复点击。
- 网关不在收到任何上游内容后自动重试。只有能够证明请求尚未写给上游的 DNS、连接或 TLS 建立失败，才允许有限的连接前重试。

### 2.4 统一答疑中心

- 学生侧边栏只有一个“答疑中心”入口，不再分别显示“AI 答疑”和“老师答疑”。
- 统一历史列表混合展示本人两种答疑，以“AI”或“老师”标签区分，并支持全部/AI/老师筛选和搜索。
- 学生发起新问题时选择“AI 即时答疑”或“老师答疑”。
- 两种通道共享标题、正文和附件编辑体验；提交后的状态机、API 和持久化域保持隔离。
- 老师端“问题答疑”只显示需要人工回复的老师答疑，不混入 AI 会话。
- 老师端新增“AI 管理”和“用量统计”。

## 3. 总体架构

采用“PostgreSQL 持久化运行 + Go 进程内兼容网关和后台运行器 + SSE”的模块化单体方案。

### 3.1 组件职责

1. **统一答疑读模型**
   - 聚合当前学生的 AI 与老师答疑摘要。
   - 只负责列表、搜索、筛选和稳定游标，不合并两个写模型。

2. **AI 配置模块**
   - 管理供应商、协议模式、模型路由、提示词、超时、价格和额度。
   - 加密、解密 API Key，并确保任何读 API 都不返回明文或密文。

3. **AI 会话模块**
   - 管理学生 AI 会话、不可变消息、附件绑定和对象归属。
   - 创建触发运行的学生消息，但不直接执行供应商调用。

4. **AI 运行模块**
   - 管理幂等创建、attempt、状态机、事件检查点、停止、失败和主动重试。
   - 在成功事务中写入最终助手消息、usage 和账本结算。

5. **兼容网关**
   - 将内部规范请求映射到 Chat Completions 或 Responses。
   - 统一解析流式增量、usage、结束原因和脱敏错误类别。
   - 执行出站地址、响应大小、事件大小和超时限制。

6. **后台运行器**
   - 从 PostgreSQL 认领排队运行，受全站和单学生并发限制。
   - 与浏览器连接解耦，批量持久化流式事件。
   - 启动时回收失去租约的运行；无法恢复原上游流时将其安全标记失败。

7. **用量模块**
   - 原子预留、释放和结算请求/Token 额度。
   - 生成按学生、模型、日期、状态和 usage 来源聚合的老师端读模型。

PostgreSQL 是运行、事件和账本的唯一事实源。Redis 只承担短期并发锁、启动速率限制等协调职责，不存放最终答案或账本。MinIO 和现有文件处理模块继续负责私有文件和安全处理产物。

## 4. 领域隔离与兼容

Phase 3 的 `qa_threads`、`qa_messages`、`qa_message_files` 和 `teacher_notes` 已经用数据库约束固定了老师/学生发送者和不可变时间线。Phase 4 不放宽这些约束。

AI 答疑建立独立表和 Go 模块，原因是：

- AI 助手没有真实 `users.id`，不应让 Phase 3 的非空发送者外键变为可空。
- 老师队列不应依赖每个查询都正确过滤 `channel` 才能避免混入 AI 会话。
- AI 运行、增量事件、重试和 usage 生命周期与老师工单状态机不同。
- 独立写模型可以在不削弱 Phase 3 安全证明的前提下演进。

两类答疑复用以下边界，而不是复用同一写表：

- 学生对象归属和越权统一 `404` 规则；
- 附件上传、扫描、文件归属和受控预览规则；
- 不可变时间线与幂等提交模式；
- Vue 时间线、附件和编辑器的展示组件；
- 统一答疑摘要接口。

## 5. 数据模型

具体列名可在实施计划中细化，但以下职责和约束是固定的。

### 5.1 配置

- `ai_providers`
  - 名称、规范化 Base URL、协议模式、加密 API Key、密钥版本、启用状态、乐观锁版本和时间戳。
  - 数据库部分唯一约束保证最多一个主供应商。
- `ai_models`
  - 供应商、上游模型标识、文本/视觉能力、上下文上限、最大输出、超时、输入/输出单价和启用状态。
  - 当前主供应商必须分别解析到一个启用的文本模型和视觉模型。
- `prompt_templates`
  - 数学/物理、版本、系统提示词、启用状态和时间戳。
  - 运行保存提示词版本与不可变摘要，历史运行不随模板修改而变化。
- `ai_global_limits` 与 `student_ai_limits`
  - 每日/月度请求和 Token 限制，保留继承/禁用/正数上限语义。

### 5.2 会话与消息

- `ai_threads`
  - `id`、`student_id`、标题、学科、最后活动时间和创建时间。
  - 学生归属和创建时间不可变。
- `ai_messages`
  - `id`、`thread_id`、角色（student/assistant）、正文、触发或生成它的 `run_id`、幂等键和创建时间。
  - 消息不可更新或删除；失败增量不伪装为完整助手消息。
- `ai_message_files`
  - 消息和 `file_versions` 的不可变绑定、顺序和展示名。
  - 只允许绑定当前学生拥有、目的为 AI 答疑且处理完成的文件版本。

### 5.3 运行与事件

- `ai_runs`
  - 会话、触发学生消息、attempt 序号、幂等键、状态、租约信息。
  - 保存供应商、模型、协议、提示词版本、配置摘要等运行快照。
  - 保存预留量、输入/输出 Token、usage 来源、费用、首字延迟、总耗时、结束原因和脱敏错误类别。
  - 同一学生和幂等键唯一；同一触发消息的 attempt 序号唯一。
- `ai_run_events`
  - `run_id`、严格递增 sequence、事件类型、内容增量和时间。
  - 事件不可变；内容按约 250 毫秒或 4 KiB 批量检查点写入，避免逐 token 写数据库。
- `ai_usage_ledger`
  - 预留、释放和结算条目，包含学生、运行、周期桶、请求数和 Token 数。
  - 运行与账本操作使用唯一约束保证最多结算一次。

运行状态为：

`queued → streaming → succeeded`

或：

`queued/streaming → failed/cancelled`

只有 `succeeded` 创建最终助手消息并消耗学生硬额度。`failed` 和 `cancelled` 释放预留，但保留脱敏运行历史。

## 6. 核心数据流

### 6.1 创建 AI 问题或追问

1. 学生提交学科、标题/正文、附件和幂等键。
2. 服务在数据层验证学生归属、附件目的、扫描/处理状态和数量/大小限制。
3. 服务读取当前启用供应商、文本/视觉模型和对应学科提示词。
4. 根据附件决定文本或视觉模型，并在服务端计算保守的输入估算与最大输出预留。
5. 在一个 PostgreSQL 事务中：
   - 锁定并检查全站/学生额度桶；
   - 创建或复用学生消息；
   - 创建唯一的 queued 运行；
   - 写入额度预留；
   - 写入必要审计事件。
6. 返回 thread、message、run 和 SSE 地址。重复幂等请求返回同一逻辑结果。

### 6.2 后台生成

1. 运行器使用数据库租约认领 queued 运行。
2. 再次验证运行快照所需的密钥版本和附件处理产物存在。
3. 构建内部规范请求；附件内容被视为不可信用户输入，不得覆盖系统指令。
4. 兼容网关验证目标地址并发起一次上游流式请求。
5. 网关解析增量，运行器批量写入有序事件；SSE 订阅者从数据库读取。
6. 成功时，在一个事务中：
   - 写入最终 assistant 消息；
   - 保存 usage、估算标记、费用和耗时；
   - 把预留转换为实际结算；
   - 将运行改为 succeeded。
7. 失败或取消时保存错误类别与终态事件，释放硬额度预留，不删除学生原消息和附件。

### 6.3 断线恢复

- SSE 事件包含稳定 `id`，等于运行内 sequence。
- 客户端通过 `Last-Event-ID` 或等价查询参数重新订阅。
- 服务端先回放大于最后 sequence 的持久化事件，再等待新事件。
- 每次订阅都重新验证会话和 thread/student 归属。
- SSE 响应设置禁止缓存和代理缓冲的响应头。
- 运行已结束时，回放遗漏事件和终态后关闭连接。

### 6.4 停止与重试

- 学生可以请求停止自己的 queued/streaming 运行。
- 取消是幂等操作；运行器收到取消后终止本地上下文，并把运行转为 cancelled。
- 已发出的上游请求可能产生未知费用，因此取消不承诺上游零成本；老师端保留 usage 未知状态。
- 只有 failed/cancelled 运行可主动重试。
- 重试创建新 attempt 和新额度预留，引用同一学生消息，不覆盖旧运行。

### 6.5 进程崩溃恢复

- 运行器周期性续租。
- 应用启动或租约到期扫描会回收 queued 运行。
- 已进入 streaming 但失去进程的运行无法安全恢复原上游连接，因此标记为 failed，释放硬额度并允许学生主动重试。
- 已持久化增量只作为失败诊断和学生可见的“未完成内容”，不写成成功答案。

## 7. 上游兼容网关

### 7.1 内部规范接口

两个协议适配器接收同一个内部请求：

- 系统提示词和已裁剪的会话上下文；
- 当前学生消息；
- 文本文档提取结果；
- 允许的图片输入；
- 目标模型、最大输出和超时；
- 内部 run ID，只用于本地关联，不依赖供应商支持幂等。

适配器输出统一事件：

- 文本增量；
- usage；
- 完成原因；
- 可重试性仅用于向学生展示，不触发不安全自动重放；
- 脱敏错误类别。

### 7.2 上下文构建

- 会话支持多轮追问。
- 从最新消息向前选择完整轮次，不拆开用户/助手配对。
- 系统提示词、当前问题和必要附件优先；超过模型上下文时先裁剪最旧历史。
- 当前问题加必要附件仍超过上限时返回 `CONTEXT_TOO_LARGE`，不静默截断当前问题。
- 文档提取文本和图片均标记为用户提供的不可信内容。
- Phase 4 不启用工具调用、网页访问、代码执行或模型驱动的任意出站请求。

### 7.3 供应商连通性测试

- 仅老师可调用，并受 CSRF、速率限制和审计保护。
- 使用最小输出的真实兼容请求验证鉴权和流格式；界面明确提示可能产生极小上游费用。
- 测试不计入学生用量账本。
- 返回协议、延迟和脱敏结果，不返回 Authorization、完整上游正文或 API Key。

## 8. API 设计

所有状态变更继续使用现有会话、CSRF、Origin 和请求 ID 中间件。最终路径可在实施计划中按现有路由风格微调，但职责不得合并。

### 8.1 学生统一答疑

- `GET /api/v1/student/question-summaries`
  - 本人 AI/老师答疑混合摘要，支持 channel、status、search 和稳定游标。
- `POST /api/v1/student/ai/threads`
  - 创建 AI 会话、首条学生消息和首个运行。
- `GET /api/v1/student/ai/threads`
- `GET /api/v1/student/ai/threads/:threadId`
- `POST /api/v1/student/ai/threads/:threadId/messages`
  - 添加追问并创建运行。
- `GET /api/v1/student/ai/runs/:runId/events`
- `POST /api/v1/student/ai/runs/:runId/cancel`
- `POST /api/v1/student/ai/runs/:runId/retries`

所有读取在 SQL 层携带当前 `student_id`。猜测他人 thread、message、run 或附件 ID 统一返回 `404`。

### 8.2 老师配置与用量

- 供应商、模型和提示词的老师端 CRUD。
- 激活一个主供应商。
- 测试供应商连接。
- 读取和修改全站/单学生额度。
- 按学生、模型、日期、状态和 usage 来源查询运行与聚合用量。

供应商读 API 只返回 `hasKey`、密钥更新时间和可选不可逆短指纹；不返回明文、密文、nonce 或 Authorization。

### 8.3 稳定错误契约

至少提供以下机器可读错误码：

- `AI_DISABLED`
- `QUOTA_EXCEEDED`
- `AI_BUSY`
- `ATTACHMENT_NOT_READY`
- `CONTEXT_TOO_LARGE`
- `PROVIDER_UNAVAILABLE`
- `RUN_FAILED`

学生看到可操作提示和 request ID。老师可以看到脱敏错误类别、HTTP 类别和时间，不看到上游秘密、学生完整正文或附件内容。

## 9. 界面设计

### 9.1 学生答疑中心

- 保留 `/student/questions` 作为统一列表入口。
- 列表混合本人两种答疑摘要，显示通道标签、标题、状态和最后活动时间。
- 新建页先选择 AI 或老师通道，再显示共享编辑器。
- 老师答疑继续使用现有详情能力。
- AI 详情显示不可变学生/助手时间线、当前额度摘要、运行状态、停止、失败重试和追问编辑器。
- AI 详情路由使用明确通道段，例如 `/student/questions/ai/:threadId`；老师详情使用 `/student/questions/teacher/:threadId`。旧老师详情链接提供兼容重定向。

### 9.2 流式渲染

- streaming 状态使用转义纯文本和 `white-space: pre-wrap`，避免不完整 Markdown/KaTeX 造成闪烁或不安全中间 DOM。
- succeeded 后才使用现有 Markdown、DOMPurify 白名单和 KaTeX 管线渲染。
- 禁止 `v-html` 直接渲染未清洗增量。
- 上游生成的链接只允许安全协议，并使用现有外部链接安全属性。

### 9.3 老师端

- “问题答疑”保持人工工单队列。
- “AI 管理”包含供应商、模型路由、提示词和额度策略。
- “用量统计”显示请求数、Token、估算费用、耗时、错误率、usage 来源和最近运行。
- API Key 输入只用于设置或替换；编辑页面只显示“已安全保存”和更新时间。

### 9.4 响应式与无障碍

- 桌面答疑中心使用历史列表/详情分栏。
- 900px 以下使用列表到详情路由导航，并提供一致的“返回答疑中心”焦点恢复。
- 所有异步状态提供可访问的加载、空、错误、重试和 request ID。
- 流式区域使用节流后的 `aria-live` 状态，不逐 token 打断屏幕阅读器。
- 尊重 `prefers-reduced-motion`，不使用依赖动画表达的生成状态。

## 10. 安全设计

### 10.1 密钥

- API Key 使用 AES-256-GCM 和随机 nonce 加密。
- 32 字节主密钥通过 Docker Secret 或受保护环境注入，不进入 PostgreSQL、镜像或仓库。
- 密文关联 key version 和 AAD；AAD 至少绑定 provider ID 和配置用途，防止密文跨记录替换。
- 解密明文只在供应商请求构建期间存在，不能进入结构化日志、错误包装或追踪字段。

### 10.2 SSRF 与出站

- 生产环境 Base URL 只允许 HTTPS。
- 拒绝 URL 用户信息、fragment 和非预期 query；端点路径由协议适配器控制。
- DNS 解析结果必须拒绝 loopback、RFC1918、链路本地、组播、保留地址和云元数据地址。
- 连接器固定使用验证后的解析结果，并在重定向时重新执行完整验证，防止 DNS 重绑定。
- 生产环境不提供“允许私网”管理开关；本地伪供应商只可通过测试/开发专用配置启用。
- 不允许老师配置任意附加请求头，只支持受控 Authorization 方式。

### 10.3 内容与附件

- 只读取当前学生拥有、用途正确、扫描通过且处理完成的附件。
- 文件正文、图片和模型输出都不能进入普通日志。
- 提示词明确把附件和历史消息视为不可信材料。
- Phase 4 不提供模型工具调用，因此内容中的指令不能触发服务器文件、网络或命令访问。

### 10.4 SSE

- 每次连接重新鉴权和对象归属校验。
- 使用 `Cache-Control: no-store`、禁代理缓冲和内容类型固定。
- 限制单事件、单运行累计输出和连接持续时间。
- 慢客户端不会阻塞供应商读取；SSE 从持久化事件独立消费。

## 11. 资源与运行限制

- 默认每名学生最多一个 queued/streaming 运行。
- 默认全站最多两个实际供应商调用并发，服务端可配置。
- 排队运行存储在 PostgreSQL，不创建无界内存队列。
- 认领使用租约和适合 PostgreSQL 的跳锁机制，避免多个运行器重复执行。
- 限制提示词、历史上下文、文档提取总字符、图片数量/尺寸、单事件大小和最大输出 Token。
- 连接、首字节、总运行和空闲流超时分别配置，并限制在服务端安全范围。
- Phase 4 不增加独立 AI Worker 容器；若以后容量证明需要，可在保持数据库租约协议的前提下拆分。

## 12. 审计与可观测性

审计以下老师操作：

- 创建/更新/启停供应商；
- 设置或替换密钥；
- 测试连接；
- 修改模型、提示词、价格和额度；
- 激活主供应商。

运行指标包括：

- queued、streaming、succeeded、failed、cancelled 数量；
- 排队、首字和总耗时；
- 输入/输出 Token、usage 估算比例、未知 usage 数量；
- 按稳定类别统计的供应商错误；
- 当前运行器租约和队列深度。

日志只包含 run ID、provider ID、model ID、状态、耗时、计数和 request ID 等非正文元数据。不得记录 API Key、Authorization、学生消息、完整答案、附件名/正文或原始上游错误体。

## 13. 测试策略

### 13.1 单元测试

- AES-GCM 加解密、错误密钥、AAD、nonce 和密钥版本；
- URL 规范化、IP 分类、DNS/重定向和 SSRF 拒绝；
- Chat Completions/Responses 请求映射和流解析；
- 运行状态机、租约、停止和重试资格；
- 请求/Token 预留、继承、禁用、并发结算和费用计算；
- 上下文裁剪、文本/视觉路由和附件状态；
- 错误分类、脱敏和安全 Markdown/KaTeX 渲染。

### 13.2 集成与契约测试

使用本地伪供应商覆盖：

- 两种协议的正常流和 usage；
- 慢首字、空闲超时、总超时和客户端断线；
- 流中断、畸形事件、超大事件、429、401 和 5xx；
- 缺失 usage、部分 usage 和结束原因异常；
- 请求尚未写出前的安全连接重试；
- 收到内容后绝不自动重放。

PostgreSQL 测试证明：

- 幂等创建不会产生重复运行；
- 多进程认领不会重复调用；
- 并发学生请求不能突破额度；
- 成功最多结算一次，失败释放一次；
- 学生 SQL 查询始终包含归属过滤；
- AI 迁移不会削弱 Phase 3 老师答疑触发器和约束。

### 13.3 前端测试

- 统一答疑列表混合排序、搜索、通道筛选和游标；
- 新建通道选择与共享编辑器；
- SSE 事件排序、重复事件去重和 `Last-Event-ID` 恢复；
- 页面刷新、重复点击、停止、失败和主动重试；
- 额度状态和稳定错误提示；
- streaming 纯文本与 succeeded 后清洗 Markdown/KaTeX；
- 手机列表/详情导航、焦点管理和无障碍状态。

### 13.4 全栈 E2E

- 老师配置、替换和测试伪供应商；
- 学生完成文字、图片、PDF 和 Word AI 答疑及追问；
- 浏览器断线后恢复同一运行；
- 失败后主动重试且不重复结算；
- AI 与老师答疑出现在同一个学生答疑中心；
- 老师人工队列不出现 AI 会话；
- 跨学生 thread/run/event/附件访问统一失败；
- API Key、Authorization 和学生内容不进入 API 响应、日志、截图或 CI 产物；
- 老师用量统计与运行/账本一致。

## 14. Phase 4 验收门槛

Phase 4 完成必须同时满足：

1. 老师可以配置并测试 Chat Completions 和 Responses 兼容供应商，完整密钥不被回显或记录。
2. 单一主供应商、文本/视觉模型和数学/物理提示词路由正确。
3. 学生可以用文字、图片、PDF 和 Word 发起 AI 答疑并多轮追问。
4. AI 与老师答疑在学生端统一展示，写模型和权限边界仍隔离。
5. SSE 刷新/断线恢复同一运行，重复点击和重连不产生重复供应商调用。
6. 成功、失败、停止和主动重试均保留一致的不可变历史。
7. 每日/月度请求和 Token 硬额度在并发下不可突破；失败不消耗学生硬额度。
8. Token、费用、耗时、usage 来源和错误类别准确或明确标记未知/估算。
9. 学生不能读取他人的 AI 会话、运行事件或附件。
10. 默认全站两并发、单学生一并发下，在目标 2 核 4 GB 环境稳定运行。
11. Go 单元/集成/race/vet/vulnerability、前端 test/typecheck/lint/build、Phase 1–4 E2E 契约和 Docker Compose 健康检查全部通过。
12. Phase 4 运维说明包含密钥注入、供应商配置、额度、故障分类、运行回收和安全诊断步骤。

## 15. 明确延后

以下内容不属于 Phase 4：

- 多供应商自动故障切换、负载均衡或学生选模型；
- 费用硬额度或自动充值；
- 工具调用、联网搜索、代码执行、RAG 或公共题库；
- 独立分布式 AI Worker 集群；
- Phase 5 的综合仪表盘、备份、监控告警和生产硬化；
- Phase 6 的正式生产发布与完整恢复验收。

Phase 4 只提供本阶段所需的 AI 管理、用量页、运行指标和运维说明，不提前实现 Phase 5 的综合运维面板。
