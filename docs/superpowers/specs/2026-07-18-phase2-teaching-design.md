# HappyLearn Phase 2 教学板块设计规格

日期：2026-07-18
状态：用户已逐节确认，待书面复核

## 1. 目标与范围

Phase 2 在已验收的 Phase 1 认证、学生管理、会话安全与审计基础上，交付“教学目录、课程编辑、课程发布、安全文件和学生学习空间”。目标环境仍为 Ubuntu 24.04、2 核 CPU、4 GB 内存、Docker 和已解析域名。

本阶段必须让老师能够从空白开始建立固定五级目录：

`年级 → 学期 → 学科 → 章节 → 课程`

老师可以编辑 Markdown + LaTeX 正文、自动保存草稿、上传和替换附件、添加外部视频、设置每个附件的预览/下载策略、选择课程对全体学生或指定学生可见，并发布不可变课程版本。学生只能搜索和阅读自己有权访问的已发布内容。

本阶段不包含：

- 作业、测验、批改、成绩、排名或完成率；
- 学生分组或班级授权；
- 教学内容评论、学生互动或公开注册；
- 课程发布站内通知，通知消费界面留到 Phase 3；
- 视频转码、自适应码率或水印；
- PDF、Office 文件内部文字搜索；
- 压缩文件上传；
- 外部视频内容抓取或代理。

## 2. 已确认的产品决定

- 目录完全由老师从空白创建，但层级固定为五级，不允许任意嵌套或子章节。
- 课程正文使用 Markdown + LaTeX，提供实时安全预览。
- 草稿自动保存；发布由老师明确确认。
- 编辑已发布课程时，学生继续看到上一发布版本，直到新版本成功发布。
- 课程可见范围为“全体启用学生”或老师逐个选择的学生。
- 学生端采用混合式学习空间：顶部筛选，左侧章节/课程列表，右侧课程正文与附件；手机端折叠导航。
- 学生可按课程标题、Markdown 正文和附件名称搜索，不搜索附件内部文字。
- 记录最近访问、是否浏览过课程和上次阅读位置，不提供手动完成和完成率。
- 本地视频单文件上限为 500 MB。常见视频均可上传；浏览器支持的格式在线播放，其他格式只允许按策略下载，不转码。
- 同时支持 HTTPS 外部视频页面 URL。只接收 URL，不接收 iframe、HTML 或脚本代码。
- Office 文件在隔离处理器中转换为 PDF/页面图后预览，文件处理并发固定为 1。
- 仅预览文件若没有成功生成可用预览，课程不得发布；系统不得自动改成允许下载。
- 每个文件独立设置“仅预览”或“允许下载”。首期不添加学生水印。
- 替换附件会生成新版本；旧版本保留 30 天，可回滚。
- 大文件采用服务端持久化的可恢复分片上传，刷新或短时断网后可继续。
- 不允许 ZIP、RAR、7Z 等压缩文件。

## 3. 总体架构

采用模块化单体方案。Vue 应用继续作为老师端和学生端界面；单个 Go 应用提供教学、上传、文件访问、学习状态 API 和静态资源托管；PostgreSQL 保存业务数据；MinIO 保存文件本体和预览产物；Redis 只承担短期协调；受限文件处理器完成恶意文件扫描和 Office/PDF/图片处理。

### 3.1 模块边界

1. `teaching`：五级目录、课程草稿、版本、排序、发布、撤回、归档和搜索。
2. `audience`：全体/指定学生策略以及学生侧对象级授权。
3. `uploads`：上传会话、分片、完成合并、校验和和过期清理。
4. `files`：文件元数据、版本、预览、引用、访问策略和访问日志。
5. `processing`：可靠任务领取、扫描、转换、重试、超时和结果写回。
6. `learning`：学生目录浏览、最近访问、已浏览状态和阅读位置。

每个模块通过窄接口通信。教学模块只依赖文件的“是否可发布”查询，不读取 MinIO 细节；文件模块不决定课程是否对某学生可见；HTTP 边界同时调用角色检查和对象级访问检查。

### 3.2 存储边界

- PostgreSQL 保存目录、正文、版本、授权、上传会话、文件元数据、校验和、引用、处理状态、访问日志和学习状态。
- MinIO 保存原文件、预览产物和未完成 multipart 对象。文件字节不写入 PostgreSQL。
- Redis 不保存业务真相。Redis 故障不能导致已发布课程、上传会话或处理任务永久丢失。
- MinIO、PostgreSQL 和 Redis 不暴露公网端口。浏览器不获得 MinIO 地址、Bucket 名或对象键。

## 4. 数据模型

所有业务标识使用不可预测 UUID，所有表包含必要时间戳。老师可见的业务删除默认使用软删除或归档；物理对象删除由延迟清理任务执行。

### 4.1 目录与课程

- `grades`：名称、排序键、归档时间。
- `terms`：所属年级、名称、排序键、归档时间。
- `subjects`：所属学期、名称、排序键、归档时间。
- `chapters`：所属学科、名称、描述、排序键、归档时间。
- `lessons`：所属章节、稳定课程身份、生命周期状态、当前已发布版本、创建/更新时间。
- `lesson_drafts`：每门课程至多一个可变草稿，包含标题、摘要、Markdown 正文、排序、自动保存版本号和更新时间。
- `lesson_revisions`：发布时创建的不可变快照，包含课程正文、标题、摘要、排序、发布人、发布时间和来源草稿版本号。

同级排序使用稀疏整数排序键；拖动排序在事务内更新，必要时重新编号。父级归档时，学生侧不能再遍历其下课程；老师端仍可查看并恢复。存在已发布课程的目录不能物理删除。

### 4.2 受众

- `lesson_draft_audiences`：草稿受众模式 `all` 或 `selected`。
- `lesson_draft_audience_users`：`selected` 模式下的学生集合。
- `lesson_revision_audiences` 与 `lesson_revision_audience_users`：发布时冻结的受众快照。

发布前必须验证所选用户仍为学生账号。学生被禁用时，即使存在发布版本授权，全局账号状态仍立即拒绝访问。老师撤回课程后，下一次请求立即失效。

### 4.3 文件与外部视频

- `files`：稳定文件身份、创建者、逻辑状态和软删除时间。
- `file_versions`：随机原对象键、规范化展示名、声明类型、探测类型、字节数、SHA-256、处理状态、创建时间和保留截止时间。
- `file_previews`：预览类型、随机对象键、页数/尺寸、处理状态和校验和。
- `lesson_draft_files`：草稿与指定文件版本的绑定、显示名、说明、排序和策略。
- `lesson_revision_files`：发布时冻结的文件版本和策略。
- `lesson_draft_external_videos` 与 `lesson_revision_external_videos`：规范化 HTTPS URL、标题、说明和排序。
- `file_access_logs`：用户、文件版本、课程版本、动作、结果、规范化客户端 IP、追踪号和时间。

附件替换创建新的 `file_versions`，不覆盖旧对象。发布版本始终引用确定的文件版本。旧版本从失去有效引用之日起保留至少 30 天；保留期内可恢复或重新绑定。

### 4.4 上传与处理

- `upload_sessions`：文件预期元数据、状态、过期时间和 MinIO upload ID。
- `upload_parts`：会话、分片序号、字节数、校验信息和 MinIO ETag。
- `file_processing_jobs`：任务类型、状态、尝试次数、可重试时间、租约、最后错误类别和时间戳。
- `outbox_events`：发布事件与后台任务事件。Phase 2 写入课程发布事件，但不发送站内通知。

上传会话默认 24 小时过期。过期清理采用保留窗口，不在请求失败瞬间删除 multipart 对象。

### 4.5 学习状态

- `lesson_progress`：学生、课程、发布版本、首次/最近访问、是否已浏览、最后阅读锚点和滚动比例。

同一学生对同一发布版本最多一条记录。新版本发布后旧记录不被覆盖；首页最近学习指向最近一次有权访问的当前发布版本。阅读位置更新需要限频，并采用后写覆盖或单调时间戳避免乱序请求回退进度。

## 5. 课程编辑与发布

### 5.1 自动保存

老师编辑标题、摘要、正文、排序、附件或受众时，前端短暂防抖后保存草稿。保存请求携带当前 `lock_version`；成功后服务端原子递增版本。若另一个标签页已经保存，服务端返回 `409 draft_conflict`，并提供重新加载提示，不进行静默覆盖。

界面明确显示“保存中”“已保存”“保存失败”和“存在冲突”。离开页面前若仍有未成功提交的修改，浏览器提示老师确认。

### 5.2 Markdown 与公式安全

- 原始 Markdown 作为课程数据保存，设置正文长度上限。
- Markdown 解析器关闭原始 HTML。
- 链接协议只允许 `https`、`http` 和必要的站内相对链接；禁止 `javascript:`、`data:` 等危险协议。
- 最终 HTML 使用严格白名单清洗后才能进入 `v-html`。
- LaTeX 渲染关闭信任模式和危险命令，并设置输入长度及复杂度限制。
- 老师预览与学生阅读使用同一渲染管线和测试用例。

### 5.3 发布

发布前在服务端重新加载并检查：

1. 五级目录均存在且未归档；
2. 标题、正文和 Markdown/LaTeX 通过验证；
3. `selected` 受众至少包含一个仍存在的学生；
4. 所有附件上传完成、扫描通过且状态为 `ready`；
5. 所有仅预览附件已经生成可用预览；
6. 外部视频是单个规范化 HTTPS URL；
7. 草稿版本号与发布请求一致。

发布事务创建不可变 `lesson_revision`，复制附件和受众快照，切换 `lessons.published_revision_id`，写入审计和 outbox。事务失败时学生继续读取旧版本。

撤回只清除当前发布指针，不删除版本。归档课程会从学生目录与搜索中移除。重新发布始终创建新版本，不修改历史记录。

## 6. 文件支持与安全

### 6.1 支持类型

首期允许：

- 文档：PDF、DOCX、XLSX、PPTX、TXT、Markdown；
- 图片：JPEG、PNG、WebP、非动画 GIF；
- 浏览器可播放视频：MP4、WebM、Ogg 视频；
- 其他常见视频：MOV、AVI、MKV，可上传但不承诺在线预览。

明确拒绝：

- ZIP、RAR、7Z 及其他压缩包；
- EXE、DLL、脚本、安装包和其他可执行格式；
- DOCM、XLSM、PPTM 等宏启用 Office 文件；
- SVG、HTML 等可携带主动内容的文件；
- 扩展名、声明 MIME、文件头和实际解析结果不一致的文件。

老师单文件统一上限为 500 MB。系统设置可以在未来下调，但 Phase 2 不提供突破 500 MB 的配置。

### 6.2 可恢复分片上传

浏览器先创建上传会话，再以默认 8 MiB 分片上传；同一上传最多并发 2 个分片。每个请求只流式传输当前分片，不在 Go 内存或临时磁盘中缓存完整文件。

分片序号和内容必须可幂等识别。重复提交同一成功分片返回已有结果；同序号不同内容返回冲突。浏览器刷新后查询已完成分片并继续。完成请求只能执行一次，并核对总大小、分片集合和最终 SHA-256。

上传过程中不信任客户端提供的对象键、ETag、MIME 或完成状态。MinIO 对象键为服务端生成的随机值，不含原文件名、学生信息或课程名称。

### 6.3 文件处理器

处理器单并发运行，并设置非 root、只读根文件系统、临时 tmpfs、移除 Linux capabilities、`no-new-privileges`、CPU/内存限制和任务超时。处理器默认无出站网络。

处理流程包括：

1. 文件头和真实类型探测；
2. 恶意文件扫描；
3. PDF 和图片结构检查；
4. DOCX/XLSX/PPTX 转换为 PDF 或页面图；
5. 视频容器、编码、时长和尺寸探测，不做转码；
6. 预览产物重新校验并写入独立 MinIO 对象。

扫描拒绝是终止状态；可恢复的转换或存储错误按有限退避重试。失败只影响相关文件，不阻塞登录和纯正文课程读取。

### 6.4 预览与下载

所有文件通过 Go 同源端点访问，不向浏览器返回 MinIO 签名地址。

- 预览端点要求登录、有效账号、当前发布版本和受众授权。
- 下载端点额外要求该版本绑定策略为“允许下载”。
- PDF、图片、Office 预览产物和浏览器兼容视频可在线显示。
- 视频端点支持合法单区间 Range 请求和拖动播放，拒绝异常或资源消耗型范围请求。
- 不兼容视频只能在“允许下载”时下载。
- 响应设置安全的 `Content-Type`、规范化 `Content-Disposition`、`X-Content-Type-Options: nosniff`、私有禁止缓存策略和必要的内容安全策略。
- 禁用学生、撤回课程或修改当前发布版本后，新请求立即重新鉴权。

“仅预览”是访问控制与产品策略，不是 DRM。系统阻止正常下载入口和下载 API，但无法阻止截屏、录屏或高级浏览器工具提取已显示内容。按用户决定，Phase 2 不添加动态水印。

### 6.5 外部视频

老师只提交 HTTPS 页面 URL。服务端解析后要求：单个绝对 URL、`https` scheme、有效主机、无凭据、无控制字符。服务端不抓取 URL，因此不会产生服务端 SSRF。

学生端以受限 `sandbox` iframe 尝试展示，不允许 `allow-same-origin`、顶层导航或任意脚本注入，并使用 `referrerpolicy="no-referrer"`。站点拒绝嵌入或播放器不兼容时，界面提供在新窗口打开。由于用户选择允许任意 HTTPS 视频页面，内容安全策略需要允许 HTTPS frame，并明确提示第三方仍可观察学生 IP 和浏览器请求。

## 7. 老师端体验

### 7.1 教学管理

`/admin/teaching` 提供五级目录树、课程列表和编辑区。老师可以创建、重命名、排序、归档和恢复目录；创建课程；查看草稿、已发布、撤回和归档状态。

课程编辑区包含：

- Markdown/LaTeX 编辑器与实时预览；
- 自动保存状态和冲突提示；
- 附件上传、续传、处理进度、重试、策略和排序；
- 外部视频 URL、标题、说明和排序；
- 全体/指定学生选择器；
- 发布前检查结果；
- 版本历史、附件回滚、撤回与重新发布。

### 7.2 文件中心

`/admin/files` 支持按文件名、类型、处理状态、引用状态和时间筛选，显示大小、版本、课程引用、预览状态、失败原因摘要和访问日志。老师可以重试可恢复任务、回滚 30 天内版本、删除无有效引用且满足保留期的文件。

任何仍被草稿或已发布版本引用的文件都不能物理删除。界面必须显示具体引用，而不是只返回笼统失败。

## 8. 学生端体验

`/student/learning` 使用已确认的混合式布局：

- 顶部选择年级、学期和学科；
- 左侧展示章节与课程列表；
- 右侧显示课程正文、外部视频和附件；
- 手机端将筛选和目录收进可访问的抽屉；
- 搜索标题、Markdown 正文和附件名称；
- 显示最近访问课程并恢复上次阅读位置。

学生只能看到当前账号有权访问的已发布版本。对不存在、未发布或无权访问的课程统一返回 `404`，防止通过 UUID 判断课程存在性。学生端不请求、缓存或渲染草稿、历史版本、受众列表、内部对象键或处理错误详情。

## 9. HTTP API 与一致性

API 按角色和用途分组：

- `/api/v1/admin/catalog/*`：目录维护与排序；
- `/api/v1/admin/lessons/*`：草稿、附件绑定、受众、发布、撤回、归档和版本；
- `/api/v1/admin/uploads/*`：创建、查询、上传分片、完成和取消；
- `/api/v1/admin/files/*`：文件中心、处理重试、引用和版本回滚；
- `/api/v1/student/catalog/*` 与 `/api/v1/student/lessons/*`：授权后的目录、搜索和课程读取；
- `/api/v1/files/{version}/preview` 与 `/download`：受控文件访问；
- `/api/v1/student/progress/*`：限频更新阅读状态。

所有状态变更请求继续使用 Phase 1 的 CSRF 与 Origin 防护。管理接口要求老师角色。学生读取在查询层带当前学生 ID 和有效账号条件，不能先读取再在 HTTP 层过滤。

列表使用游标或稳定分页并设置上限。自动保存、分片上传、上传完成和发布接口具备明确幂等或乐观并发语义。数据库约束负责唯一性、合法状态、有效引用和不可变发布版本。

## 10. 错误处理与审计

对外错误继续返回稳定错误码、可理解说明和追踪 ID。至少定义：

- `draft_conflict`；
- `upload_expired`、`upload_part_conflict`、`upload_incomplete`；
- `file_type_rejected`、`file_too_large`、`file_scan_rejected`；
- `file_processing_failed`、`preview_not_ready`；
- `lesson_not_publishable`；
- `range_not_satisfiable`。

内部日志不得包含文件正文、完整外部 URL 查询秘密、会话令牌、对象键或学生选择清单。老师的目录变更、发布、撤回、归档、受众变化、文件策略变化、处理重试、版本回滚和删除操作写入不可变审计日志。

访问日志记录预览、下载、拒绝和失败，但不记录文件内容。高频视频 Range 请求按一次播放会话聚合或采样，避免日志膨胀，同时保留拒绝和异常范围请求。

## 11. 资源与部署约束

Phase 2 的 Compose 增加私有 MinIO 和文件处理服务。目标资源控制：

- Go 文件传输保持近似恒定内存，不缓冲完整文件；
- 文件处理并发固定为 1；
- 大文件分片上传并发默认 2；
- Office 转换和扫描设置硬超时与内存上限；
- MinIO、PostgreSQL、Redis 仅在 Docker 私有网络监听；
- 持久卷分别保存数据库和 MinIO 数据；
- 服务使用非 root、健康检查、日志轮转和受控重启策略。

Phase 2 必须提供开发环境初始化、MinIO Bucket 创建、处理器健康检查、孤儿分片清理和数据备份注意事项。完整 Caddy 公网部署与自动备份编排仍属于后续阶段，但本阶段镜像和 Compose 必须可在目标服务器结构中运行。

## 13. Phase 2 验收标准

1. 老师能从空白创建、排序、归档和恢复固定五级目录。
2. 老师能用 Markdown + LaTeX 编辑课程，自动保存并看到明确保存状态。
3. 已发布课程的新草稿不会影响学生正在读取的旧版本。
4. 老师能发布全体或逐个学生可见的课程；无权学生始终无法确认课程存在。
5. 500 MB 内文件支持刷新或断网后的可恢复上传，Go 不缓冲完整文件。
6. 允许类型经过真实类型校验和扫描；压缩包、可执行文件、宏 Office 和主动内容文件被拒绝。
7. Office 文件成功转换后在线预览；转换失败或仅预览产物缺失时课程不能发布。
8. 浏览器兼容视频支持 Range 播放；其他视频只在允许下载时提供下载。
9. 外部视频只接受 HTTPS URL，以受限 iframe 尝试展示，失败时可安全跳转新窗口。
10. 每个附件的仅预览/允许下载策略在后端强制执行，并留下访问日志。
11. 文件替换生成版本，旧版本保留 30 天可回滚，有效引用阻止物理删除。
12. 学生端提供混合式布局、授权搜索、最近访问和上次阅读位置恢复。
13. 禁用学生、撤回课程或切换发布版本后，下一次文件和课程请求立即重新鉴权。
14. PostgreSQL、Redis 和 MinIO 不暴露公网端口，处理器单并发且受资源和网络限制。
15. 全套单元、集成、竞态、前端、浏览器、安全、漏洞和 Docker 验证通过，无未处理的 Critical 或 Important 审查问题。

## 14. 实施分解建议

Phase 2 适合拆为四个连续交付门：

1. 教学目录、草稿、发布版本、受众和学生只读目录；
2. MinIO、可恢复上传、文件元数据、访问策略和日志；
3. 隔离扫描/转换、文件中心、视频与外部视频；
4. 老师编辑器、学生混合式学习空间、搜索、学习状态和全链路验收。

每个门都必须使用 TDD、数据库集成测试和独立代码审查。上一门的安全与一致性检查未通过前，不进入下一门。
