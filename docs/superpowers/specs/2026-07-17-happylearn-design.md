# HappyLearn 网页端家教平台设计规格

日期：2026-07-17  
状态：已由用户逐节确认

## 1. 项目目标

HappyLearn 是部署在个人 Linux 云服务器上的网页端家教平台，面向一名高中数学、物理老师及 1–50 名学生。产品采用类似 Sub2API 的高密度侧边栏控制台信息架构，分为老师管理端和学生端，业务集中于教学内容发布和私密答疑。

平台优先保证以下目标：

1. 老师可以集中管理学生、教学资料、答疑、AI 接口和用量。
2. 学生可以按课程结构学习老师发布的资料，并选择 AI 或老师答疑。
3. 学生数据严格隔离；每名学生只能查看自己的答疑。
4. AI API Key、教学文件、答疑附件及学生信息得到端到端保护。
5. 系统在 Ubuntu 24.04、2 核 4 GB、已有 Docker 和已解析域名的服务器上稳定运行。
6. 数据库、文件和备份具备可恢复、可审计、可验证的运维流程。

## 2. 已确认范围

### 2.1 用户与角色

- 系统只有一个老师超级管理员账号。
- 不提供公开注册；所有学生账号由老师创建。
- 学生首次登录必须修改临时密码。
- 首期仅支持密码登录，不启用双因素认证。
- 数据模型保留未来扩展多老师角色的可能性，但首期不提供多老师功能或界面。

### 2.2 教学板块

教学内容按以下固定层级组织：

`年级 → 学期 → 学科 → 章节 → 课程`

其中学科首期主要为高中数学和高中物理。老师可以：

- 创建、编辑、排序、发布、撤回和归档目录与课程；
- 为课程编写正文并上传多个附件；
- 使用草稿和发布状态；
- 查看文件引用、版本、预览/下载记录和存储占用；
- 为每个文件独立设置“仅在线预览”或“允许下载”。

学生只能查看已发布内容。PDF、图片、视频及可安全转换的 Office 文件支持在线预览；允许下载的文件仍需登录和权限校验。

### 2.3 答疑板块

学生提交题目时主动选择一种答疑通道：

1. **AI 答疑**：平台立即调用老师配置的 OpenAI 兼容接口，默认直接返回完整解答，包括条件整理、公式、推导步骤、最终答案和必要验算。
2. **老师答疑**：系统创建私密答疑工单，老师使用文字和附件回复，学生可在同一会话中继续追问。

两类答疑均支持文字、多张图片、PDF、Word 及经允许的常见附件。所有答疑默认且永久为私密数据，不建立公共答疑库，学生之间不能查看问题、回复、姓名或附件。

老师答疑状态为：

`待处理 → 处理中 → 等待学生 → 已完成`

老师可以重新打开已完成答疑。消息和附件保留完整时间线，不允许静默覆盖历史记录。

### 2.4 明确排除

首期不包含：

- 作业、测验、自动或人工批改；
- 成绩、排名、学习评价；
- 公共题库或公共答疑；
- 学生互相查看或交流；
- 公开注册、邀请码注册；
- 在线支付；
- 多老师协作与分级管理。

## 3. 技术方案

采用 Go + Vue 的模块化单体架构。

### 3.1 前端

- Vue 3 + TypeScript + Vite；
- Vue Router 管理老师端与学生端路由；
- Pinia 管理会话、权限和界面状态；
- Element Plus 构建 Sub2API 风格的高密度控制台；
- KaTeX 或 MathJax 渲染数学、物理公式；
- Markdown 内容经过严格白名单清洗后渲染；
- 响应式布局覆盖桌面和手机浏览器。

### 3.2 后端

- 单个 Go 应用提供 REST API、流式 AI 响应、静态前端托管和后台任务入口；
- 使用清晰模块边界隔离认证、教学、答疑、文件、AI、用量、通知、审计和系统设置；
- PostgreSQL 驱动使用原生参数化查询或代码生成查询，禁止拼接 SQL；
- 数据库迁移随应用版本管理，迁移默认保持向后兼容；
- OpenAPI 描述关键接口并用于契约验证。

### 3.3 基础设施

- Caddy：HTTPS、反向代理、安全响应头、请求大小限制和访问日志；
- PostgreSQL：用户、课程、答疑、消息、配置、用量、通知和审计数据；
- MinIO：教学文件、题目附件、老师答疑文件、预览产物和必要的临时对象；
- Redis：登录限速、短期缓存、分布式锁和轻量任务队列；
- 隔离文件处理器：Office/PDF 内容提取、预览转换和恶意文件扫描；
- 备份任务：数据库和对象存储的一致性备份及保留策略。

上述服务由 Docker Compose 管理。PostgreSQL、Redis 和 MinIO 仅连接 Docker 私有网络，不映射公网端口。

## 4. 产品信息架构

### 4.1 老师端菜单

1. **仪表盘**：学生数、待答疑数、AI Token/费用、错误率、存储占用、最近活动、备份和系统健康。
2. **学生管理**：创建、禁用、启用、重置密码、设置 AI 限额、查看登录记录和导出单个学生数据。
3. **教学管理**：维护年级、学期、学科、章节、课程、正文、排序和发布状态。
4. **文件中心**：上传、预览、下载策略、版本替换、引用检查、存储占用和访问审计。
5. **答疑管理**：按状态、学生、时间筛选；回复文字、上传附件、添加仅老师可见的内部备注。
6. **AI 管理**：配置供应商、Base URL、API Key、模型、接口模式、超时、重试、提示词、额度和启停状态。
7. **用量统计**：按学生、模型和日期查看请求数、Token、估算费用、耗时和错误率。
8. **通知与审计**：站内通知、登录记录、管理操作、AI 配置变更和文件访问记录。
9. **系统设置**：站点信息、上传限制、安全策略、备份状态、数据保留、存储状态和健康检查。

### 4.2 学生端菜单

1. **学习首页**：最近课程、新发布内容、未读通知和最近答疑。
2. **教学板块**：按年级、学期、学科和章节浏览课程。
3. **文件学习**：安全预览，以及按老师配置下载文件。
4. **AI 答疑**：提交文字和附件，查看流式完整解答。
5. **老师答疑**：提交私密问题、查看状态和回复、继续追问。
6. **我的答疑**：搜索和筛选仅属于本人的历史答疑。
7. **通知中心**：课程更新和老师回复通知。
8. **账号设置**：修改密码、查看活跃会话、退出其他设备。

学生端不渲染管理菜单，后端也拒绝学生访问任何管理接口。

## 5. 核心领域模型

### 5.1 认证与用户

- `users`：账号、角色、状态、密码哈希、首次改密标志和时间戳；
- `sessions`：会话摘要、设备信息、IP、到期时间和撤销时间；
- `login_events`：成功/失败、原因、IP、设备和时间；
- `student_ai_limits`：单学生每日/月度请求、Token 或费用限制。

### 5.2 教学内容

- `grades`、`terms`、`subjects`、`chapters`、`lessons`：固定层级和排序；
- `lesson_revisions`：课程正文与发布版本；
- `files`：对象键、原始名称、真实类型、大小、校验和、扫描/转换状态；
- `file_bindings`：文件与课程、答疑消息等业务实体的关联；
- `file_policies`：仅预览或允许下载；
- `file_access_logs`：用户、文件、动作、IP、结果和时间。

### 5.3 答疑

- `qa_threads`：学生、通道、标题、状态和时间；
- `qa_messages`：发送者、消息类型、正文、AI 状态和不可变时间线；
- `qa_message_files`：消息附件关联；
- `teacher_notes`：仅老师可见的内部备注；
- `ai_runs`：供应商、模型、请求状态、Token、估算费用、耗时、错误类别和幂等键。

### 5.4 配置、通知与审计

- `ai_providers`：Base URL、加密 API Key、接口模式和状态；
- `ai_models`：模型标识、能力、上下文限制、单价、超时和启用状态；
- `prompt_templates`：数学/物理系统提示词及版本；
- `notifications`：接收者、类型、内容、已读时间和业务链接；
- `audit_logs`：管理操作、配置变更、对象摘要、IP 和时间；
- `outbox_events`：事务性通知和后台任务事件；
- `system_settings`：非秘密站点设置；
- `backup_runs`：备份批次、范围、结果、校验和和恢复验证状态。

业务表使用不可预测的 UUID 类标识。外键、唯一约束、检查约束和必要索引由数据库强制执行。审计记录不保存密码、完整 API Key 或学生文件正文。

## 6. 核心数据流

### 6.1 发布教学内容

1. 老师选择年级、学期、学科和章节，创建课程草稿。
2. 老师编辑正文并上传附件。
3. 后端校验权限、大小、扩展名、MIME 和文件头，计算校验和，以随机对象键写入 MinIO。
4. PostgreSQL 保存文件元数据、业务关联、处理状态和下载策略。
5. 隔离任务完成扫描、内容提取和预览转换。
6. 老师发布课程；事务同时写入课程版本与 outbox 事件。
7. 后台任务根据 outbox 创建学生站内通知。

草稿对学生不可见。撤回和重新发布均保留版本与审计信息。

### 6.2 AI 答疑

1. 学生提交文字和附件，后端验证本人身份、额度和文件安全状态。
2. 系统创建答疑线程、用户消息和处于排队状态的 AI 运行记录。
3. 文件处理器按类型安全提取文本、页面图像或可供视觉模型使用的内容。
4. AI 网关使用版本化的数学/物理提示词构建请求，并调用老师配置的 OpenAI 兼容 API。
5. 后端将流式内容转发给学生，并在服务端聚合完整答案。
6. 成功后原子性保存最终答案、模型、Token、估算费用和耗时。
7. 中断或失败时保存错误类别与可重试状态，不把部分回答标记为完成。

重试使用幂等键。同一次 AI 运行不得因前端刷新、网络重连或重复点击而重复记账。

### 6.3 老师答疑

1. 学生提交问题，系统创建待处理线程并通知老师。
2. 老师查看全部上下文，切换为处理中，回复文字或上传答疑文件。
3. 回复写入不可变消息时间线，同时创建学生通知。
4. 学生可以追问，线程变为等待老师或处理中。
5. 老师完成线程；以后仍可重新打开。

## 7. AI 网关与用量

老师端可以配置一个或多个 OpenAI 兼容供应商，但首期同一时间只启用一条主线路。每项配置包括：

- 名称、Base URL、API Key；
- Chat Completions 或 Responses 兼容模式；
- 文本模型和视觉模型；
- 模型能力、上下文限制、单价和启停状态；
- 连接超时、首字节超时、总超时和有限重试；
- 全站及单学生每日/月度额度；
- 额度字段语义固定为：空值继承全站默认值，0 表示禁用，正数表示对应周期上限；
- 数学、物理提示词及版本。

后台提供连通性测试，但不在响应或日志中暴露密钥。API Key 使用 AES-256-GCM 加密，主密钥通过 Docker Secret 或受保护的服务器环境注入。

用量统计以供应商返回的 usage 为优先；供应商未返回时使用明确标记的估算值。统计维度包括学生、模型、日期、成功/失败、输入/输出 Token、估算费用、首字延迟和总耗时。

## 8. 文件安全与访问

### 8.1 上传

- 按业务类型配置允许扩展名和最大尺寸；
- 默认限制为：学生单张图片 20 MB、最多 10 张，单个 PDF 50 MB，单个 Office 文件 30 MB，单次答疑全部附件合计 100 MB；老师单个教学文件 500 MB。老师可在系统设置中向下调整或在服务器容量允许时显式上调；
- 同时校验扩展名、声明 MIME、文件头和实际解析结果；
- 对象键使用随机值，不包含用户输入；
- 原始文件名规范化后仅作为展示元数据；
- 拒绝可执行文件、宏启用 Office 文件及嵌套压缩炸弹；
- 文件扫描/转换在无出站网络、限 CPU/内存、只读根文件系统的隔离容器中执行；
- 扫描未完成或失败的文件不可发布给学生。

### 8.2 预览与下载

- MinIO Bucket 全部私有；
- 每次访问先由 Go 后端验证登录、角色、业务归属和文件策略；
- 仅预览内容通过受控预览端点或默认 5 分钟有效的授权访问；
- 允许下载内容使用默认 60 秒有效、限定单个文件的授权地址；
- 预览页面叠加学生姓名、账号和当前时间动态水印；
- 旧授权链接到期后不能继续使用；
- 每次预览、下载、拒绝和失败均记录审计日志。

### 8.3 删除与保留

业务删除先软删除，默认保留 30 天。后台延迟清理任务只有在确认无有效业务引用、超过保留期并留下审计记录后才删除 MinIO 对象。版本控制用于恢复误替换或误删除文件。禁用学生账号不会自动删除课程访问记录或答疑；永久清除必须由老师执行单独的二次确认操作。审计日志默认保留 365 天。

## 9. 身份、会话与权限安全

- 密码使用 Argon2id，参数在实现阶段通过基准测试确定并记录；
- 首次登录强制修改临时密码；
- 使用高熵、不透明会话令牌；服务端仅保存令牌摘要；
- Cookie 设置 `HttpOnly`、`Secure` 和合理的 `SameSite`；
- 状态变更请求启用 CSRF 防护；
- 登录按账号和 IP 限速，连续失败后临时锁定并按风险触发验证码；
- 普通会话默认空闲 7 天失效、最长 30 天失效；首次改密和密码重置后撤销其他会话；
- 用户可以撤销其他设备会话；管理员禁用学生时立即撤销其全部会话；
- 每个后端接口同时执行角色检查和对象归属检查；
- 学生查询在数据访问层强制包含当前学生标识，避免仅在控制器层过滤；
- 错误响应不透露账号是否存在、数据库结构、对象键或内部堆栈。

## 10. 错误处理与一致性

- 对外错误包含稳定错误码、用户可理解的说明和追踪编号；详细上下文只进入脱敏服务端日志。
- 数据库事务覆盖课程发布、答疑消息、AI 最终记账等原子操作。
- outbox 模式保证业务状态和通知/后台任务不会一边成功一边丢失。
- AI 调用具备超时、有限重试、熔断和幂等保护；只有可安全重试的错误才自动重试。
- AI、MinIO 或文件处理暂时不可用时保留原始业务记录和明确状态，恢复后可继续执行。
- 文件上传采用“临时对象 → 数据库确认 → 正式关联”流程；孤儿对象由有保留窗口的清理任务处理。
- 删除、发布、重置密码、AI 配置变更等敏感操作写入审计日志。

## 11. 通知

首期只提供站内通知：

- 学生收到课程发布/更新、老师回复和答疑状态变化通知；
- 老师收到新的老师答疑、学生追问和关键系统告警；
- 通知支持已读/未读、批量标记和跳转到业务对象；
- 未读数在控制台导航栏实时或短轮询更新。

通知模块定义通道接口，未来可以增加邮件和微信适配器，但首期不实现外部通道。

## 12. 部署与资源控制

目标环境为 Ubuntu 24.04、2 核 4 GB、Docker 和已解析域名。Docker Compose 服务包括：

- `caddy`
- `app`
- `postgres`
- `redis`
- `minio`
- 受限的文件处理/扫描任务
- 定时备份任务

部署要求：

- 镜像使用明确版本和不可变摘要，不使用漂移的 `latest`；
- 容器使用非 root 用户、最小 Linux capabilities、只读根文件系统和受控持久卷；
- 每个服务设置健康检查、日志轮转、重启策略和内存/CPU 上限；
- 文件转换任务限制并发为 1，防止 Office/PDF 处理耗尽内存；
- Caddy 只开放 80/443，SSH 由服务器自身安全策略管理；
- HTTP 访问日志不记录签名参数、会话标识或其他敏感查询字符串；
- 应用启动先检查配置和迁移状态，健康后才接收流量；
- 发布前创建备份，失败时可回退上一版本镜像；
- 数据库迁移优先采用扩展后收缩策略，避免回滚时旧版本无法读取。

## 13. 备份、监控与审计

### 13.1 备份

- PostgreSQL 每日 03:00（Asia/Shanghai）逻辑备份；重要升级前创建额外备份；
- MinIO 开启对象版本控制；
- 数据库与对象存储备份共享批次标识和清单；
- 本机默认保留最近 7 个每日备份；配置独立服务器或 S3 兼容存储后，默认保留 30 个每日备份和 12 个每月备份；
- 备份文件加密并限制文件系统权限；
- 恢复目标为 RPO 不超过 24 小时、RTO 不超过 4 小时；
- 每季度及重大数据库迁移后恢复到空环境，校验课程、答疑、附件和引用一致性；
- 恢复演练结果写入 `backup_runs` 并显示在老师仪表盘。

### 13.2 监控

监控至少覆盖：

- 容器存活、CPU、内存和重启次数；
- 磁盘空间、MinIO 容量和对象错误；
- PostgreSQL 连接、事务和备份状态；
- AI 成功率、错误率、首字延迟、总耗时和费用；
- 文件处理队列长度和失败数；
- 登录失败、权限拒绝和异常下载频率。

日志采用结构化格式、自动轮转和字段脱敏。不得记录密码、完整 API Key、会话令牌、学生文件正文或完整 AI 请求附件。

## 14. 测试策略

### 14.1 单元测试

- 密码、会话和首次改密；
- 角色权限与学生对象归属；
- 教学层级和发布状态；
- 答疑状态机；
- AI 限额、Token 和费用计算；
- 文件策略、保留期和清理判断；
- 错误映射和敏感字段脱敏。

### 14.2 集成与契约测试

- PostgreSQL 约束、事务、迁移和 outbox；
- Redis 限速、锁和队列；
- MinIO 上传、授权、版本和删除；
- 文件类型探测、隔离转换和失败恢复；
- OpenAI 兼容 Chat Completions/Responses 流式协议；
- AI 超时、断流、错误体、重试和幂等记账。

### 14.3 端到端测试

- 老师创建学生，学生首次登录并改密；
- 老师发布课程和两种文件策略；
- 学生预览、允许下载和被拒绝下载；
- 学生完成 AI 答疑和老师答疑多轮流程；
- 学生无法读取他人答疑或管理接口；
- 老师查看用量、审计和系统健康；
- 手机与桌面浏览器关键路径。

### 14.4 安全与恢复测试

- 暴力登录、账号枚举、CSRF、越权、ID 猜测和会话撤销；
- 恶意文件名、伪造 MIME、超大文件、压缩炸弹和危险 Office 文件；
- Go、前端依赖、容器镜像和 Web 基线漏洞扫描；
- 从 PostgreSQL 与 MinIO 备份恢复到空环境，并执行引用一致性检查。

## 15. 首版验收标准

1. 老师可创建、禁用、启用和重置学生账号，学生必须在首次登录修改临时密码。
2. 老师可按固定层级维护并发布高中数学、物理课程及附件。
3. 文件的仅预览/允许下载策略在后端强制执行，过期链接不可复用。
4. 学生可使用文字、多图、PDF 和 Word 发起 AI 或老师答疑。
5. AI 答疑可流式返回完整解答，并准确记录成功、失败、Token、估算费用和耗时。
6. 老师答疑支持多轮消息、附件、状态变化、站内通知和重新打开。
7. 学生只能访问自己的答疑，越权测试全部失败且留下安全日志。
8. AI、MinIO 或文件处理故障不丢失学生原始问题，并能在恢复后安全重试。
9. 老师可以配置和测试 OpenAI 兼容接口，但前端、日志和 API 响应不暴露完整密钥。
10. PostgreSQL 与 MinIO 的自动备份、恢复演练、健康检查和审计日志均可验证。
11. 关键功能在桌面和手机浏览器可用。
12. 整套服务在目标 2 核 4 GB 服务器上通过资源和稳定性验证。

## 16. 实施分期

为控制风险，完整首版按以下可独立验证的阶段实施：

1. 工程基础、Docker、数据库、认证、权限和审计；
2. 教学层级、课程编辑、文件上传、预览和下载策略；
3. 老师答疑、消息时间线和站内通知；
4. AI 网关、附件内容处理、流式回答、用量与限额；
5. 仪表盘、系统设置、备份、监控和安全加固；
6. 全链路测试、恢复演练、服务器部署和验收。

每个阶段必须通过相应测试和安全检查后再进入下一阶段。
